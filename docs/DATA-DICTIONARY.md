# 数据定义

票号与原始编号均为字符串，保留前导零。称重支持 kg、公斤与 t，统一为 kg，单价为 CNY/kg。
毛重与皮重按票号和版本配对，品类、单价、扣杂率与更正目标必须一致。计价重量=(毛重−皮重)×(1−扣杂率)，先量化到0.001kg，再乘单价，金额四舍五入到0.01CNY。
每票第一版不填写 replaces。后续版本只能替代当前生效版，分支或缺基版整票阻断结算。已支付额为各版本中最大累计已付值，待付=最终应付−累计已付；负待付表示待收回。
同编号同原值仅计一次；同编号不同原值全部隔离。空文件、全空行和仅表头分别报错。原始输入计数包括空行及重复表头，对账会分别解释。
归档封存保存逐版证据、隔离原因和运行摘要，非支付执行系统。数据使用虚构编号，不连接实际支付渠道。

## 主体净额

主体登记为票号→主体的映射，同一票号出现两个主体即主体身份冲突。船款登记号 `ref` 全局唯一，同 ref 金额或主体不一致即登记冲突；`state` 为 `closed` 才计入净额（`open` 暂缓）。`pending_corrections` 记录尚未闭合的迟到复秤或扣杂更正，命中票暂缓。`netting_policy` 可选 `closed_first`（默认，已闭合票先出令）或 `all_confirmed`（同主体全部票与船款确认后才轧差）。

净额=Σ纳入票待付−Σ纳入船款。待付为票的最终应付减累计已付，负值表示应收回。净额正数划付主体，负数向主体收取，零表示无需划转。指令 `command_id` 由谱系、净额依据、整户状态与暂缓原因共同哈希，同输入重跑不变。指令台账按谱系逐版记录 `supersedes`，仅可出令的版本成为生效指令，暂缓版本保留证据但不顶替上一版。导出包 `netting.json` 保存指令与台账，`source.csv` 为原始凭证字节。
